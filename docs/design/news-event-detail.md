## 当前阅读顺序

| 区域 | 已记录内容 |
| --- | --- |
| 概览 | 当前版本的实际送达标题／来源标题、状态、完整发布时间与时区、实际来源和平台、收到至送达耗时、资产与复制链接 |
| 读者收到的推送 | 原样冻结正文；可可靠拆分时按冻结 claim refs 顺序展示中文行，编号回链到事实。未确认送达时明确状态，有关联的此前实际正文直接可读 |
| 每件事与推送原因 | 全部采用事实，编号不变，已送达事实优先；中文来自同版实际发送行，英文原文为次级信息；未发送、等待、失败、撤回及分歧都有明确文字 |
| 原文 | 真实来源名称、发布时间、外链及保存的正文；精确引用高亮保留所有重叠事实编号，截断标记与未匹配引用不伪装完整覆盖 |
| 同一个故事 | 同故事线、收到时刻前后各 24 小时的事件、来源、状态与送达时间；最多本条及最近 29 条，超限明确提示 |
| 用时 | 收到到当前版本最后送达／本次决定的真实时间；仅显示保存的规划、召回、判断、卡片、等待发送及发送测量 |
| 工程细节 | 默认折叠，保留处理、逐条计划、原始字段、历史比较、推断与缺口、材料、时间线、回执及关联查询 |
| 当前行情 | 默认折叠，保留关联资产、来源、价格种类、时钟、陈旧状态和滚动 24H 口径 |

桌面使用主阅读列与故事／用时侧列。窄屏 DOM 与视觉顺序相同：主文、事实、原文、故事／用时，再查看工程细节和行情。复用工作台外壳与现有 token，不复制静态原型的独立导航。

## 数据与交互边界

- 当前 adopted revision 或有效决定版本的 `sent` 意图提供“本次已推送”事实及中文。通知工作已完成且仍指向旧版、head 没有 `NOTIFICATION_CHANGES` 时沿用该决定，保留真实 `decided_revision` / `decided_at_ms`；pending / failed 旧工作不沿用，通知变化冲突显示“通知状态异常”。只有被新事实取代的历史发送单独折叠。
- 沿用后新增来源的卡片仍直接可读，原事实判断、概率和阈值保留；概览、卡片下注与派生时间线注明新增来源和沿用时间。真实“通知决策”步骤保持原决定时间，不伪造新决定。
- 无通知工作的已采用复述显示“重复”，仍归入“未推送”。通过采用历史的 `previous_content_ref` / `previous_ref` 查原条及真实回执；即使原条未推送，本条也不重新判断。读者区和每件事都可打开原条，时间线派生“不建立通知：本版本只有复述”。
- 卡片解析首先验证冻结摘要，再要求标题、行数与排序后的唯一 claim refs 精确匹配。不能拆分时显示完整原文，不按采用顺序分配中文，也不在读取时调用翻译模型。
- 此前推送只查询实际 `sent`、早于当前决定的账本行。优先使用持久 anchor；老记录从冻结模型上下文或已记录语义路径解析，不用同故事线代替关系。新增可选 anchor 在为空时不改变旧 ReaderRecord 的序列化身份。
- 列表理由先解释标题那件事，再列“另 N 件：…”；现代判断显示推送概率和推送线，旧模型显示“旧版模型判断：只进信息流”。过时原因指事实首次出现超过 3 小时，详情显示该事实的首次出现时间，不把新来源称为过时。浏览器将结构化时间按本地时区显示，CLI 保留 UTC。
- `?focus=news-claim-3`、`?focus=source-01` 与工程记录冷链接可分享、刷新和后退。引用定位打开目标祖先 details 并聚焦；轮询只更新数据。已分享的旧 tab query 定位对应段落，新页面已删除 tab／隐藏 panel／高度槽实现。
- 原文逐字保留。重叠引用合并标记编号；找不到的引用仍有事实回链。来源正文超过服务端保存投影上限时明确显示节选。
- 复制保留当前阅读 query。详情刷新失败保留成功内容并提示缓存时间，冷读取和报价各自支持真实重试。手机主要动作和展开行至少 44px；状态不只靠颜色表达。
- 同故事线只是浏览范围，具体“补充／更正／读者已知”由已记录决定和关系解释。缺失时间与阶段不补算；当前报价不是事件后收益。
