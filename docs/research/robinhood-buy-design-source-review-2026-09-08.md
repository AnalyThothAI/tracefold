## 2. 原样本支持什么，不支持什么

#572 正文自己声明样本有界、处于新链早期、不能外推；但“最有效的是减仓/清仓核实卡”写成了强结论。它的支持材料包括站点和 Fomo 已展示买入、跟随者相对领头者入场溢价较高，以及买卖后的价格方向差异。这足以提出“买入需区分时机”“卖出可能补充信息”的研究假设，无法完成“退出最优”的证明。[#572 §2–§4、§10](https://github.com/AnalyThothAI/tracefold/issues/572)

具体限制如下，均为对原方法的分析：

1. **研究目标不同。** “信息有没有被别人广播”“用户是否从中发现值得研究的对象”“按该信息下单能否赚钱”是三个问题。即便 Fomo 已经广播买入，聚合、筛选、识别连续加仓、对比入场位置仍可能为用户节省研究时间。信息公开不等于信息无用，也不保证存在交易优势。
2. **样本不足以比较买卖效果。** 原事件研究只有 21 个买入样本和 40 个卖出样本，买后 1 小时 tape 末价中位约 +17%、卖后约 −5%。它没有说明匹配的无信号基线、事件前趋势、共同市场变化、同币重复事件相关性和真正可成交价格。这里是相关观察，不能读成卖出导致下跌，更不能给两个方向排出可靠优劣。[#572 §3.2](https://github.com/AnalyThothAI/tracefold/issues/572)
3. **原站 tape 的不完整性也会污染研究。** 原调查认为 tape 缺少大量平仓对应成交；用同一 tape 衡量前后跟随次数与末价，会同时受缺样和稀疏成交影响。后来换成链上采集解决了部分输入问题，不会自动追认旧统计结论。[#572 §3.1–§3.3](https://github.com/AnalyThothAI/tracefold/issues/572)
4. **名单构造、事件规则与频次目标混在了一起。** 把名单扩至 147 人、窗口延长至 60 分钟可以增加候选数，却改变了“共振”的含义。新事件最多证明两个被跟踪地址在一小时内达到买入金额要求；两个地址不等于两个独立观点，更不等于两个经过验证的优秀交易者。
5. **质量榜本身还是待检验的特征。** 已实现盈亏比单看胜率更接近收益，但短期盈亏排序仍受资金体量、极端大赢家、持仓未兑现、交易环境影响。适合将 `rank_quality` 展示为当时站点统计筛选的标签，不能命名为已证实的“聪明钱能力”。
6. **“买入时能知道什么”必须严格限定。** 事后得到的 7 天榜单、今日 bag 均价、今日最深池、最终平仓结果，都不能作为历史事件当时已知的输入。历史回补如果绑定接收时才生成的名单版本，也不能声称模拟了当时实时选人。

买入事件应该先被保留下来，再研究条件差异。例如首次观察到的大额买入、已有持仓上的持续加仓、平仓后重新进入、第二个地址接力，可能表现完全不同；直接把它们统一归为“已经晚了”会把要研究的问题提前判掉。

### 3.3 Fomo 的公开产品表述不能替代效果证据

Fomo 当前官网仍宣传发现和关注交易者、实时买入通知，并自称有 500,000 名交易者。这能够确认买入信息传播是产品卖点；不能证明每个名单钱包都有自动跟单者、所有买入已无信息增量，或卖出是市场上唯一尚未推送的内容。[Fomo 官网](https://fomo.family/)

DEX Screener 官方说明 token/pair 查询可以提供 `priceUsd`、`liquidity`、`marketCap` 等可空字段。它们适合来源明确的市场快照；这些字段不是给定金额订单的成交承诺，也没有因此成为事件时点的历史报价。[DEX Screener 官方接口](https://docs.dexscreener.com/api/reference)

## 4. 以“买入研究”重新定义输出

建议把首要问题写成：**最近有哪些代币出现了值得检查的买入行为，谁在什么阶段买、这笔买入对该钱包有多重要、现在相对可观察入场位置发生了什么、有哪些事实削弱这一判断？**

研究主单元可以是“代币的一轮买入观察”，从首个满足研究条件的已计价买入开始，随同币后续买卖更新。这一单元可以独立于是否发送通知存在；通知只挑选用户当下需要看到的变化。无需等待第二个地址才开始研究，也不应把窗口累计买入等同于新仓。

| 输出问题 | 最少事实 | 缺失时如何表达 |
| --- | --- | --- |
| 谁买了什么 | 链/代币合约、钱包、链上成交身份、数量、现金腿、买入方向 | 无现金腿或无法可靠分类则排除出已确认买入金额统计，保留缺失原因 |
| 是新仓、加仓还是重入 | 事件前余额或已覆盖的持仓段历史、历史覆盖起点、普通转入转出 | 只说“观察期首次买入”，不能说“首次建仓” |
| 买入有多重要 | 本笔和本轮累计金额；该钱包此前买入金额分布；若有可靠总资金口径再计算仓位占比 | 没有钱包资产分母时不生成“重仓”；同样 $1,000 对不同钱包不是同一强度 |
| 是否有后续确认 | 加仓次数、净数量/净现金变化、其他名单地址加入的时间与金额 | 说“多个地址”，不把相近时间或关联持币直接升级成“独立共识” |
| 现在进入会有多晚 | 首笔成交均价、达到候选条件的时刻、当时市场价格、当前市场价格及时间、流动性 | 缺少同时点可比价格就不能生成追高百分比，更不能用不同时刻、不同币向的报价硬算 |
| 哪些事实削弱买入线索 | 原买入者随后卖出、持仓无法核实、流动性下降、报价过期、来源缺口 | 在该候选下列出相关变化，独立于“推荐卖出” |
| 为什么值得用户检查 | 与同窗其他候选相比的可读排序理由 | 没有验证过的综合得分时使用少量明确字段排序，不制造伪精确评分 |

**名单身份、交易者质量、入场阶段是三个不同轴。** 保留全 147 人有助于观察，不代表全部通过绩效筛选。`rank_quality` 可以成为解释标签；应通过未来样本检验它是否比全名单有增量。巨额买入、连续加仓、多地址加入也分别作为观察特征，先不要压成一个不可解释分数。

对摘要，建议程序先产出按代币聚合的候选事实包：本轮何时开始、累计多少买入、参与者与质量标签、已知持仓阶段、价格位置、相关卖出与缺失项。模型回答“新增买入研究对象”和“已有对象发生了什么变化”；用户不关心的孤立卖出可以留在事实层与详情，卖出只有在解释某个买入对象的状态时才占据摘要位置。这是输出目标设计，并不要求删除卖出数据。

模型逐行引用 fact id、数字对账仍应保留。但**数字存在于事实包不等于解释正确**：“两个地址买入”不能自动改写成“市场共识”，“净现金回收为正”不等于“当前持仓利润”，“现在没有 bag”也不能无条件声称“本笔全仓退出”。对账还要覆盖实体、时点、量纲与状态含义，至少通过少量真实事实包人工验收这些表述。

## 5. 最小可评价的数据闭环

目前文档中的回执围绕已发送退出/拥挤卡，在发送后取 1h/4h 价格。它能描述这些卡之后市场价格的变化；没有覆盖全部未发送买入候选、真实可执行成交价、机会遗漏或用户研究价值，因此不宜直接称为买入策略收益。[现有回执口径](../OPERATIONS.md#the-four-hourly-buy-digest-614)

下面是最小研究协议建议，不是预设盈利策略：

1. **冻结问题和时点。** 每条候选写清 `detected_at`、所用事件截止时点、信息实际取得时间、当时的规则版本与名单版本。回补候选单独标识为回顾性发现，不充当实时历史表现。
2. **冻结当时的输入。** 买入事实引用既有 ledger 身份；钱包指标使用候选生成之前已取得的快照；价格保留来源、池子、quote token、计价方向、实际采样时点。未来名次和未来最深池不能回填成过去输入。结构化字段可以复用既有事实包和 evidence，但评估的固定键需可查询。
3. **保存所有符合研究定义的候选。** 已发送、未发送、去重合并、因缺数据不进入排序都保留原因。否则只能计算“我们最终挑出来并能定价的幸存者”，无法知道遗漏了多少。
4. **先比较少量可解释基线。** 在同一固定前瞻窗口，比较“全部计价买入”“原拥挤条件”“买入优先候选”。再分别检验质量标签、相对金额、连续加仓是否增加信息。避免同一天反复调阈值直至历史表现最好。
5. **价格结果与执行结果分开。** `P(t+h)/P(t)-1` 只是一段价格变化；给定金额下的模拟结果需单独考虑可取得的报价、延迟、费用、滑点和失败。如果尚未取得这类证据，就报告价格观察结果。任何实际代币买卖都不在本文范围。
6. **短时点要贴合买入问题。** 在现有 1h/4h 之外，优先补一个 15m 观察，而不是立刻铺满大量 horizon。实际采样偏离目标的秒数与无价格比例必须一起报告；拿晚很多的价格冒充目标时点会误导快节奏样本。
7. **按独立机会检查不确定性。** 同币拆单、同轮多次提醒、同日市场行情不能都当成独立成功样本。报告去重候选数、唯一代币/钱包/天数、每日分布、缺样率，以及最差结果；有足够观察后再估计按代币/日期成组的不确定性。
8. **保留失败样本。** 没有后续价格、池子消失、无足够流动性、来源中断的候选应作为显式结果。只在能成功定价的行上计算平均涨幅会隐去困难案例。未知不是零收益，也不是可以悄悄删除的行。

反复从同一历史片段挑名单、阈值和窗口，会产生选择偏差；仅展示最好的一组回测无法说明未来有效。Bailey 等的原始研究专门讨论反复尝试策略造成的假发现，以及普通 holdout 在这种情形下的限制。这里最省事的第一步是登记试过的少数方案、冻结输入并积累新的前瞻样本，不是马上引入复杂优化器。[The Probability of Backtest Overfitting，作者预印本](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

评估应同时回答三类问题：

| 目标 | 最先观察的量 | 不能用来替代它的量 |
| --- | --- | --- |
| 数据可信 | 当前链高水位落后、名单/报价年龄、分类未知率、缺价格率、候选时点可复现率 | worker 进程存活或卡片成功发送 |
| 用户研究有用 | 用户标注“值得继续看”的比例、重复内容比例、首次发现时效、重要买入遗漏例子 | 每天恰好发够某个数量的卡 |
| 后续市场差异 | 从可用观察时点开始的价格分布、扣除成本的模拟结果（有证据后）、相对基线增量 | 领头者本人实现盈利或单个大涨案例 |

## 6. 模块与 seam 的最小设计

沿用现有链上 ledger、名单快照、市场 Item、通知和审计 LM，不新建平行采集系统。当前优先需要的是把“买入研究候选”这个语义收敛到一个 module：调用方提交一个有截止时点的已持久化事实窗口，取得候选及其依据。持仓阶段、累计买入、关联卖出、价格新鲜度的解释应集中在其 implementation 中，模型与卡片不各写一套。这个 interface 的价值在于让读者输出和评估跨同一条 seam 检验，而不取决于内部文件数量。

保持以下职责可分别阅读和验证：

- **采集事实**：只回答可审计的链上动作，名单决定观察范围，外站统计保持来源身份。
- **形成买入候选**：以 as-of 事实窗口计算候选、状态、排序理由和缺失；这也是评估输入。
- **表达与通知**：确定性事实先排序，模型缩写解释；发送只影响触达，不改变事实与评估样本。
- **结果观察**：按既定时点写结果，不反向改写当初候选或历史钱包质量。

这不是要求立刻抽四个新 module 或增加四套 interface；现有函数与表能承载就直接复用。特别是只有一个实际来源时，不为假想 provider 增加抽象。原方案的“Qwen 不进热路径”还应对照现实：Operations 明确记载摘要调用运行在 tape 的 turn 内，最长 60 秒会暂停该 turn 的采集。这对时效敏感的买入研究是可以测量的延迟因素；后续是否拆出调度应由实际延迟和用户时效要求决定。[摘要运行说明](../OPERATIONS.md#the-four-hourly-buy-digest-614)

建议实施顺序是：先核对公开域名兼容性与现有事实新鲜度；再将摘要和控制台组织为买入优先并人工检查真实事实包；随后记录全部买入候选的固定时点与前瞻结果；最后用新样本决定是否值得扩大识别规则、名单质量评估或更低延迟采集。不要以“已有减仓通知很多”替代买入研究的完成标准。

## 7. 本次研究边界与未决事实

- 没有重跑 #572 的原始事件研究，也没有原 19.5 小时 tape 的冻结原始数据，因此正文旧数值只作历史依据，未声称独立复现。
- 147 人是本次公开接口快照与 #572 当时记录共同支持的站点名单数量；不代表已经核对当前生产名单、排名、通知数量或完整全链范围。
- API 301 与新域 200 是本次直接观察；实际生产是否使用旧域、是否已经降级、错误持续多久仍需运行证据。
- 原站提供的成本、盈亏、粉丝与持仓是外部报告；链上成交 ledger 也需要确认其分类覆盖、缓存时点和普通转账处理，不能把所有缺口交给模型猜测。
- 本文没有证明任何买入特征存在可交易优势；它给出如何避免过早否定买入研究、如何最少改动获得可比较证据的路径。
