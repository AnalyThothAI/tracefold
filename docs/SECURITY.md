# Security and authority

[Handbook](README.md) · [Setup](SETUP.md) · [Operations](OPERATIONS.md)

Security boundaries protect real credentials, data and account authority. They are
not extra review ceremonies or a reason to add a second simulator/configuration
system. This page owns those boundaries; module guides own behavior.

## 1. Secret handling and configuration

Never print, log or commit provider tokens, cookies, API keys, private keys or
populated operator configuration. Use `tracefold config` for redacted paths and
configured/readable state; do not copy full `~/.tracefold/config.yaml` into logs,
chat, issues or test fixtures.

The operator config is `~/.tracefold/config.yaml`, generated by `tracefold init`.
There is no `.env`, alias config or environment-variable shadow schema. Ordinary
initialization preserves existing config/password contents and repairs required
permissions; `init --force` replaces config defaults, not database passwords.

Secret files must satisfy the current [secret-file validator](../tracefold/platform/config/secret_file.py):
regular non-symlink files, bounded size and private permission bits. Empty execution
or Telegram placeholders mean unconfigured, not valid credentials. A requested
but invalid credential-dependent boundary must fail with a sanitized reason.

[Typed settings](../tracefold/platform/config/models.py) and [Compose](../compose.yaml)
own the actual inventory and mounts. The bootstrap PostgreSQL credential is not
an application mount. The ordinary database credential is shared by application
roles, which still expose bounded repository capabilities. Telegram's token-file
mount belongs to News Workers; only Nautilus receives Binance credential-file
mounts. A shared application image does not imply shared execution authority.

The config contains provider/model settings needed by configured roles; do not
claim it is completely secret-free merely because a role lacks Binance files.
Diagnostics and model/learning artifacts must exclude credentials and secret URLs.
Credential-free evidence, prompts, cards, manifests and receipts may be published
when authorized; that publication does not make proposed labels accepted truth.

## 2. HTTP and browser access

Public HTTP is **read-only**: every current `/api/*` operation is GET, and Serve's
public database pool is read-only. `/api/bootstrap` discloses the configured bearer
for those browser reads. The setting name `ws_token` does not mean a WebSocket
client or a browser command token. There is no manual-order HTTP route.

The bootstrap/read bearer is not a replacement for deployment access control.
Publishing a console beyond its intended network exposes whatever read data the
HTTP boundary makes available. Review bind/public URL and network/proxy access
before doing so. Do not confuse a local-development token with a separate capital
authority scheme.

Workers probes expose their supported health/readiness/metrics surfaces, not a
Telegram command webhook. Status availability and runtime health do not authorize
placing orders or mutating accepted history.

## 3. Operator and execution authority

`tracefold trading issue` is the explicit local operator ingress, authenticated
through the local OS identity. It records bounded, expiring intent; recording is
not proof the Runtime accepted it or the venue completed it. Read subsequent
observations and venue evidence. [Generated CLI help](generated/cli-help.md) owns
the current arguments, and [Operations](OPERATIONS.md) the procedures.

The independent Nautilus process is the only account-facing execution owner.
News and Trading Analysis have no order-write tool. Signal publication, Runtime
configuration and an operator request remain separate boundaries. There is one
configured Binance connection, not an in-process Paper simulator.

A documentation PR, frontend build, model evaluation or historical replay does not
authorize starting/restarting the Runtime, changing account configuration, submitting
orders, merging or deploying. Authorized operational changes must preserve actual
permission, freshness, concurrency, sizing and protection checks. Stopping a
process must remain possible even when readiness reports it blocked.

Unknown venue evidence is not a flat position. A timeout is not proof an order
was rejected. Preserve protection and reconcile according to the owning adapter
rather than blindly retrying or inventing a successful execution. See
[Execution](modules/execution.md).

## 4. Model capability boundaries

| Model consumer | Permitted role | Not permitted |
| --- | --- | --- |
| News Agent | Incremental structured extraction and bounded judgments, adopted EventUpdates and one reserved read of supplied stored material | Arbitrary web/shell tools, invented source facts or account actions |
| Notification planner / composer | Claim-level coverage judgments and on-demand copy for selected adopted claims | Retraction of adopted knowledge on card failure or Trading authority |
| Trading ReAct Agent | Bounded read-only Case evidence tools, finite plan selection and attributable claims | Arbitrary tool execution, order placement, sizing or new permissions from source text |
| Retained card judge | Bounded calibration of reader copy quality | Changing EventUpdate truth, accepting its own labels or granting execution authority |

Source text and tool results are untrusted data, not instructions that enlarge
capabilities. Validate output shapes, visible references, plan identities and
budgets in code. Unknown errors must not turn into fabricated favorable decisions.
The [News](modules/news.md), [Trading](modules/trading.md), and
[Learning](modules/learning.md) guides identify the concrete owners.

Semantic checkpoints and observations bind the full frozen input, program and
model identities; credentials do not belong in those artifacts. Physical model
calls and uncertainty are separate from logical stages. There is no fixed
three-request formula for the EventUpdate/judgment/notification path.

## 5. Reviews, datasets and release evidence

An assisted proposal is not accepted Gold; acceptance records the actual reviewer
and evidence. AI-authored text must not be relabeled as independent human review.
The old optimization/release/canary execution is removed. Retained historical
artifacts confer no current release authority, and calibration does not modify
accepted reviews or activate a News model.

Preserve frozen evidence and identity when replaying. A model route change is not
a new label, a higher training metric is not observed reader quality, and a research
price-path return is not native execution PnL. Historical results apply to their
recorded source/data/protocol; do not replace them with current reruns in place.

## 6. Change and verification scope

Changes affecting credentials, account commands, execution, destructive migrations
or exposure require the corresponding explicit operational authorization. Do not
add unrelated approval gates to ordinary isolated source/documentation work.
Keep transactions short, preserve actual data/permission controls, and run checks
that exercise the affected boundary. Never replace missing verification with a
claim that live systems or accounts were tested.

Use [public API contract tests](../tests/contract/test_openapi_drift.py),
[backend boundaries](../tests/architecture/test_backend_boundaries.py), and the
[module-specific tests](README.md) alongside the applicable operational procedure.
